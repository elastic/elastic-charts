Rendering without a browser

@elastic/charts/headless renders a chart to a string in plain Node. It needs no DOM, no jsdom and no canvas.

import { Chart, Settings, Axis, BarSeries, Position, ScaleType } from '@elastic/charts';
import { renderChart } from '@elastic/charts/headless';

const html = renderChart(
  <Chart id="revenue" size={{ width: 600, height: 300 }}>
    <Settings showLegend />
    <Axis id="left" position={Position.Left} />
    <BarSeries id="bars" xScaleType={ScaleType.Ordinal} xAccessor="x" yAccessors={['y']} data={data} />
  </Chart>,
);

Input​

A <Chart> element, passed directly rather than wrapped in another element or component. The chart needs positive numeric width and height in pixels, since there is no container to measure. For example, use size={400}, size={[400, 300]} or size={{ width: 400, height: 300 }}. CSS strings such as "400px" and "100%" are not supported. The renderer prop is ignored: the chart is always drawn as SVG.

Use the same installed copy and module format of @elastic/charts for renderChart and every chart component: use import for both entry points, or require for both. The ESM and CommonJS builds have separate chart contexts, so mixing components from them can cause an error or produce an empty chart.

Output​

One root <div class="echChart"> as a string. Inside it:

  • the chart drawn as an inline <svg>, with real <text> elements;
  • the legend, metric panels and line annotation markers as HTML, exactly as in a browser.

The Chart's title and description props are omitted. Add a heading or description outside the returned markup if needed. Axis titles and metric titles are still rendered.

The markup needs a Charts stylesheet on the page that hosts it, see Adding the stylesheet.

Ids inside the <svg> start with the chart's id, so several charts can share a page. Give each chart its own id; without one a random id is used and the markup differs between runs.

In a browser, do not reuse the id of a chart that is mounted on the page: the ids in the markup would collide with that chart's.

<Settings debugState /> adds the debug state as the data-ech-debug-state attribute, as in a browser.

Adding the stylesheet​

The parts of the chart get their layout from CSS classes: where the <svg> and the legend sit inside the root element, how legend items flow, how metric text is arranged and truncated. The markup carries only the computed parts, such as sizes and series colors, as inline styles. Without a Charts stylesheet the legend and the metric panels are unstyled and the parts are misplaced. What is drawn inside the <svg> does not depend on it.

In a web app a bundler turns a stylesheet import into page CSS. Node has no such step, so read the file as text and put it wherever the CSS of your page goes:

import { readFileSync } from 'node:fs';
import { createRequire } from 'node:module';
import { renderChart } from '@elastic/charts/headless';

const require = createRequire(import.meta.url);
const css = readFileSync(require.resolve('@elastic/charts/theme_only_light.css'), 'utf8');

const page = `<style>${css}</style>${renderChart(chart)}`;

In a CommonJS module require.resolve is already available, so the createRequire lines are not needed.

Which file to use:

FileContentsUse it when
theme_only_light.css, theme_only_dark.cssThe styles of the chart components, nothing else.The page has styles of its own. This is the usual choice.
theme_light.css, theme_dark.cssThe same, plus two page-wide rules: the font family of html and body, and the letter spacing of SVG text.The page holds nothing but charts.

Pick light or dark to match the theme of the chart. Colors that the chart draws come from the theme you pass in Settings, but the color of the legend text and of the "no data" message comes from the stylesheet.

The stylesheet is the same for every chart, about 35 kB, so add it once per page, not once per chart.

What the stylesheet expects of the page​

The stylesheet is written for a page that has EUI's global styles, as Kibana does. None of the four files includes those styles or EUI's reset: theme_light.css and theme_dark.css add only the two page-wide rules listed above. On any other page the HTML parts of a chart need four things that EUI's styles would have provided:

  • The font of the page. Legend text and annotation markers take their font family, size and line height from the page. EUI sets Inter at 14px with a line height of 16px.
  • Border-box sizing. Without it the metric text is taller than its panel and the value is cut at the bottom.
  • No default margins, paddings or list bullets. The metric grid is a list with a heading and paragraphs in it, which browsers indent, space out and mark with a bullet.
  • Legend text of 12px. The stylesheet sizes it in rem against EUI's root font size of 14px. With the usual root of 16px the legend text is drawn larger than it was measured, and gets cut.

These rules provide all four inside the chart and nowhere else. With them, every element of the chart is laid out the same as on a page with EUI's global styles:

.echChart {
  font: 400 14px/1.1428571429 Inter, BlinkMacSystemFont, Helvetica, Arial, sans-serif;
}
:where(.echChart) *,
:where(.echChart) *::before,
:where(.echChart) *::after {
  box-sizing: border-box;
}
:where(.echChart) :is(ul, li, h2, p, figure) {
  margin: 0;
  padding: 0;
  list-style: none;
}
.echChart :is(.echLegendItem__label, .echLegendItem__legendValue, .echLegendTable__cell, .echLegend__legendValue, .echReactiveChart_noResults) {
  font-size: 12px;
}

Put them after the Charts stylesheet and after the page's own styles. The two middle rules weigh no more than a rule for a bare element, so that the stylesheet's own rules win over them. They win over page rules such as p { margin: 1em 0 } only by coming later, and a more specific page rule, such as .content p, still reaches into the chart. Use the font family of the chart's theme in the first rule.

Text measurement​

Layout depends on the width of text: axis sizes, legend size, label fitting, metric text size. Without a browser, text is measured with the advance widths of Inter, the first font of the default theme, for printable ASCII characters.

  • The size and the weight of the font are honored. The font family is not: text is measured as Inter even when the theme names another font.
  • Kerning is left out, so a text is measured up to a few percent wider than a browser draws it, or a fraction of a percent narrower.
  • Any other character counts as one average glyph, so text in another script can overflow or be cut early.
  • The markup only names the font of the theme. It does not carry the font.

So the result is close to a browser's when the page draws the chart in Inter. Inter has to be installed where the markup is drawn, or loaded by the page with @font-face. Otherwise the text is drawn in the next font of the list or in a fallback, and one with wider glyphs can cut labels that were measured to fit.

Not supported​

  • Word cloud, flame and timeslip charts, which draw on a canvas of their own. renderChart throws for them.
  • Interactions: tooltips, hover, brushing and legend actions need a browser.
  • Listeners of Settings, the props that start with on, such as onRenderChange and onProjectionAreaChange, are not called. Functions that shape what is drawn are: accessors, formatters, and sort functions such as legendSort and renderingSort.
  • The markerBody of a line annotation is in the markup, but stays next to its marker: a browser measures it and moves it to keep it inside the chart.

Example: a Node project​

Two files make a project that renders two charts in Node and writes them, with the stylesheet, into one HTML file that any browser shows without running a script.

package.json, with the peer dependencies of Charts spelled out:

{
  "name": "chart-headless-test",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node index.mjs"
  },
  "dependencies": {
    "@elastic/charts": "latest",
    "moment-timezone": "^0.5.32",
    "react": "^18.0",
    "react-dom": "^18.0"
  }
}

Install and run. Both steps can be repeated: the first does nothing when the dependencies are in place, the second overwrites chart.html.

yarn && yarn start

To try a version that is not released yet, replace latest with the address of a package tarball. Every pull request of this repository publishes one, linked as "Packages" in the deployment comment of the pull request. A tarball made locally with npm pack in packages/charts works too, as file:./elastic-charts-<version>.tgz. Yarn identifies a tarball by its name and version, so a tarball packed again does not reach a project that has installed it before. Reinstall from scratch: remove node_modules, yarn.lock, and the folder of @elastic/charts in the yarn cache (yarn cache dir).

index.mjs uses createElement in place of JSX, so it needs no build step:

import { readFileSync, writeFileSync } from 'node:fs';
import { createRequire } from 'node:module';

import { Axis, BarSeries, Chart, LineSeries, Metric, Position, ScaleType, Settings } from '@elastic/charts';
import { renderChart } from '@elastic/charts/headless';
import { createElement as h } from 'react';

const data = ['Mon', 'Tue', 'Wed', 'Thu', 'Fri'].flatMap((day, i) => [
  { day, visits: [12, 19, 7, 15, 22][i], site: 'docs' },
  { day, visits: [8, 11, 14, 9, 17][i], site: 'blog' },
]);

const xy = renderChart(
  h(
    Chart,
    { id: 'xy-chart', size: { width: 600, height: 300 } },
    h(Settings, { showLegend: true, legendPosition: Position.Right }),
    h(Axis, { id: 'days', position: Position.Bottom, title: 'day' }),
    h(Axis, { id: 'visits', position: Position.Left, title: 'visits' }),
    h(BarSeries, {
      id: 'bars',
      xScaleType: ScaleType.Ordinal,
      yScaleType: ScaleType.Linear,
      xAccessor: 'day',
      yAccessors: ['visits'],
      splitSeriesAccessors: ['site'],
      data,
    }),
    h(LineSeries, {
      id: 'target',
      xScaleType: ScaleType.Ordinal,
      yScaleType: ScaleType.Linear,
      xAccessor: 'day',
      yAccessors: ['target'],
      data: data.filter(({ site }) => site === 'docs').map((d) => ({ ...d, target: 15 })),
    }),
  ),
);

const metric = renderChart(
  h(
    Chart,
    { id: 'metric-chart', size: { width: 600, height: 160 } },
    h(Metric, {
      id: 'metric',
      data: [
        [
          { color: '#16C5C0', title: 'Requests', subtitle: 'per second', value: 1234, valueFormatter: (d) => `${d} rps` },
          { color: '#A6EDEA', title: 'Error rate', value: 0.7, valueFormatter: (d) => `${d}%` },
        ],
      ],
    }),
  ),
);

// the Charts stylesheet, read as text: there is no bundler here to turn an import into page CSS
const require = createRequire(import.meta.url);
const css = readFileSync(require.resolve('@elastic/charts/theme_only_light.css'), 'utf8');

// what the Charts stylesheet expects of its page, which EUI's global styles provide in Kibana:
// the font, border-box sizing, no default margins, paddings or bullets, and legend text of 12px
const hostStyles = `
  .echChart { font: 400 14px/1.1428571429 Inter, BlinkMacSystemFont, Helvetica, Arial, sans-serif; }
  :where(.echChart) *, :where(.echChart) *::before, :where(.echChart) *::after { box-sizing: border-box; }
  :where(.echChart) :is(ul, li, h2, p, figure) { margin: 0; padding: 0; list-style: none; }
  .echChart :is(.echLegendItem__label, .echLegendItem__legendValue, .echLegendTable__cell, .echLegend__legendValue, .echReactiveChart_noResults) { font-size: 12px; }
  body { font-family: Inter, BlinkMacSystemFont, Helvetica, Arial, sans-serif; margin: 24px; }
  .box { border: 1px solid #cad3e2; margin-bottom: 24px; }
`;
// The page names Inter and does not load it. Where Inter is not installed, a browser draws a fallback font,
// while the text was measured as Inter: add an `@font-face` rule for Inter to see the layout as measured.

const page = `<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>@elastic/charts/headless</title>
    <style>${css}</style>
    <style>${hostStyles}</style>
  </head>
  <body>
    <div class="box" style="width: 600px; height: 300px">${xy}</div>
    <div class="box" style="width: 600px; height: 160px">${metric}</div>
  </body>
</html>
`;

const out = new URL('./chart.html', import.meta.url);
writeFileSync(out, page);
console.log(`document is ${typeof document}; wrote ${page.length} characters to ${out.pathname}`);

Example: a single HTML page​

renderChart also runs in a browser, which makes for a quick way to look at its output. The page below loads React and the other dependencies of Charts from esm.sh, calls renderChart for an XY chart and a metric chart, and assigns each returned string to the innerHTML of an empty element. Nothing on the page is mounted by React.

It loads Charts from a local checkout of this repository, so three things have to be in place:

  • A peer directory. Save the page as index.html in a directory next to the checkout, for example chart-headless-test beside elastic-charts. The page reaches the build through the relative path ../elastic-charts/packages/charts/dist.
  • A build. Run yarn build in elastic-charts/packages/charts first. It produces both the modules and the stylesheets under dist.
  • A server over the parent directory. Browsers do not load modules from file://, so serve the directory that holds both, on this machine only:
npx http-server .. -a 127.0.0.1 -p 8377 -c-1

Run it in the directory of the page, then open http://127.0.0.1:8377/chart-headless-test/.

In a browser a canvas exists, so text is measured with it. The Inter width tables are used only where there is no document, as in Node. The page adds the rules from What the stylesheet expects of the page.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>@elastic/charts/headless test</title>

    <!-- The Charts stylesheet: layout of the legend, the metric panels and the placement of the svg -->
    <link rel="stylesheet" href="../elastic-charts/packages/charts/dist/theme_only_light.css" />
    <style>
      /* The page names Inter and does not load it: where Inter is not installed, a fallback font is drawn. */
      body { font-family: Inter, BlinkMacSystemFont, Helvetica, Arial, sans-serif; margin: 24px; background: #fff; color: #1d2a3e; }
      /* What the Charts stylesheet expects of its page, which EUI's global styles provide in Kibana:
         the font, border-box sizing, no default margins, paddings or bullets, and legend text of 12px. */
      .echChart { font: 400 14px/1.1428571429 Inter, BlinkMacSystemFont, Helvetica, Arial, sans-serif; }
      :where(.echChart) *, :where(.echChart) *::before, :where(.echChart) *::after { box-sizing: border-box; }
      :where(.echChart) :is(ul, li, h2, p, figure) { margin: 0; padding: 0; list-style: none; }
      .echChart :is(.echLegendItem__label, .echLegendItem__legendValue, .echLegendTable__cell, .echLegend__legendValue, .echReactiveChart_noResults) { font-size: 12px; }
      .box { width: 600px; height: 300px; border: 1px solid #cad3e2; margin-bottom: 24px; }
      #log { white-space: pre-wrap; font: 12px ui-monospace, monospace; color: #516381; }
    </style>

    <!-- `external=react,react-dom` makes every package share the one React of this import map. -->
    <script type="importmap">
      {
        "imports": {
          "@elastic/charts": "../elastic-charts/packages/charts/dist/esm/index.mjs",
          "@elastic/charts/headless": "../elastic-charts/packages/charts/dist/esm/headless/index.mjs",

          "react": "https://esm.sh/react@18.3.1",
          "react-dom": "https://esm.sh/react-dom@18.3.1?external=react",
          "react-dom/server": "https://esm.sh/react-dom@18.3.1/server?external=react",
          "react-redux": "https://esm.sh/react-redux@9.2.0?external=react,react-dom",
          "@reduxjs/toolkit": "https://esm.sh/@reduxjs/toolkit@2.12.0?external=react,react-dom",
          "re-reselect": "https://esm.sh/re-reselect@4.0.1",

          "@popperjs/core": "https://esm.sh/@popperjs/core@2.11.8",
          "bezier-easing": "https://esm.sh/bezier-easing@2.1.0",
          "chroma-js": "https://esm.sh/chroma-js@2.4.2",
          "classnames": "https://esm.sh/classnames@2.2.6",
          "d3-array": "https://esm.sh/d3-array@1.2.4",
          "d3-cloud": "https://esm.sh/d3-cloud@1.2.5",
          "d3-scale": "https://esm.sh/d3-scale@3.3.0",
          "d3-shape": "https://esm.sh/d3-shape@2.1.0",
          "luxon": "https://esm.sh/luxon@1.28.1",
          "moment-timezone": "https://esm.sh/moment-timezone@0.5.35",
          "ts-debounce": "https://esm.sh/ts-debounce@4.0.0",
          "utility-types": "https://esm.sh/utility-types@3.10.0",
          "uuid": "https://esm.sh/uuid@14.0.0"
        }
      }
    </script>
  </head>
  <body>
    <h1>renderChart → innerHTML</h1>
    <p>Nothing below is mounted by React. Each box gets a string from <code>renderChart</code> as its <code>innerHTML</code>.</p>

    <div id="xy" class="box"></div>
    <div id="metric" class="box" style="height: 160px"></div>
    <div id="log"></div>

    <script type="module">
      import React from 'react';
      import { Chart, Settings, Axis, BarSeries, LineSeries, Metric, Position, ScaleType } from '@elastic/charts';
      import { renderChart } from '@elastic/charts/headless';

      const h = React.createElement;
      const log = (text) => (document.getElementById('log').textContent += text + '\n');

      const data = ['Mon', 'Tue', 'Wed', 'Thu', 'Fri'].flatMap((day, i) => [
        { day, visits: [12, 19, 7, 15, 22][i], site: 'docs' },
        { day, visits: [8, 11, 14, 9, 17][i], site: 'blog' },
      ]);

      try {
        const start = performance.now();
        const xy = renderChart(
          h(Chart, { id: 'xy-chart', size: { width: 600, height: 300 } },
            h(Settings, { showLegend: true, legendPosition: Position.Right }),
            h(Axis, { id: 'days', position: Position.Bottom, title: 'day' }),
            h(Axis, { id: 'visits', position: Position.Left, title: 'visits' }),
            h(BarSeries, {
              id: 'bars', xScaleType: ScaleType.Ordinal, yScaleType: ScaleType.Linear,
              xAccessor: 'day', yAccessors: ['visits'], splitSeriesAccessors: ['site'], data,
            }),
            h(LineSeries, {
              id: 'target', xScaleType: ScaleType.Ordinal, yScaleType: ScaleType.Linear,
              xAccessor: 'day', yAccessors: ['target'], data: data.filter((d) => d.site === 'docs').map((d) => ({ ...d, target: 15 })),
            }),
          ),
        );
        document.getElementById('xy').innerHTML = xy;

        const metric = renderChart(
          h(Chart, { id: 'metric-chart', size: { width: 600, height: 160 } },
            h(Metric, {
              id: 'metric',
              data: [[
                { color: '#16C5C0', title: 'Requests', subtitle: 'per second', value: 1234, valueFormatter: (d) => `${d} rps` },
                { color: '#A6EDEA', title: 'Error rate', value: 0.7, valueFormatter: (d) => `${d}%` },
              ]],
            }),
          ),
        );
        document.getElementById('metric').innerHTML = metric;

        log(`two charts rendered to strings in ${(performance.now() - start).toFixed(1)} ms`);
        log(`xy markup: ${xy.length} chars, metric markup: ${metric.length} chars`);
      } catch (error) {
        log(`FAILED: ${error.stack ?? error}`);
        throw error;
      }
    </script>
  </body>
</html>
